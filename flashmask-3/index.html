Overview

The attention mask has become the bottleneck

Packed long-context batches carry structured masks (document, prefix-LM, share-question, sliding-window, block-sparse). Under multi-node context parallelism (CP), the mask itself dominates step time.

Three costs appear once masks meet CP:

  • Materialization: dense n×n masks do not fit long contexts.
  • Mask-aware scheduling: kernels must skip masked work without stalling the pipeline.
  • Mask-induced imbalance: equal-length shards carry very unequal work.

FlashMask already compresses masks to O(n) with four column-wise boundary vectors (LTS, LTE, UTS, UTE), but it targets Ampere and has no distributed support.

Key observation. The column-wise mask is indexed by key but stores query-row boundaries. That single asymmetry makes per-rank localization a zero-communication elementwise map, and the same full / partial / unmasked tile classification can drive every layer of the stack.

Method · §3.1

A third warp role that reads the mask

FA3's producer warp group has 128 threads, yet one thread is enough to issue each TMA load, so 96 threads sit idle every iteration. FlashMask-3 turns them into a KV Index Generator that classifies tiles from the boundary vectors, so masking never enters the WGMMA critical path.

Method · §3.2

Zero-communication mask localization

Keys are all-gathered, so every rank already holds every key column of the O(n) mask. It only has to renumber each row boundary into its own rows. That is a purely local count, so zero bytes cross ranks.

Method · §3.3

Balance the work, not the length

CP cuts the query axis into N = P·κ chunks and gives each rank κ of them. Under structured masks, chunks of equal length carry very different work, and step time is set by the slowest rank. HCC-IPO minimizes that makespan Φ under the cardinality constraint.

Method · §3.4

Hide communication behind sparse attention

CP must all-gather K,V in the forward pass and reduce-scatter dK,dV in the backward pass. FlashMask-3 runs both on 4–8 SMs of high-priority streams, overlaps them with a single unsplit attention kernel, and never sends a chunk that the mask fully hides (≈50% of AG/RS traffic on causal and prefix-LM document masks). End-to-end throughput rises by 7.3–11.0% while attention forward+backward gets 24.5–44.9% faster. The gap is expected: in the full configuration attention is only 43.5% / 25.8% / 24.4% of forward+backward compute, and the end-to-end step also includes gradient synchronization and the optimizer update, which FlashMask-3 does not touch. Hierarchical routing is what lets balancing and overlap compose across nodes: without it the balancer spreads chunks over nodes, inter-node traffic grows, and the combination (−1.7% / −1.5% / +1.9%) falls below overlap alone.
